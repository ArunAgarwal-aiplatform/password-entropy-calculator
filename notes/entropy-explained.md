In cybersecurity, entropy is a measure of unpredictability or randomness. When it comes to passwords, higher entropy means a password is harder for an attacker to guess or crack using brute-force methods. Entropy is measured in bits.

Think of entropy bits like the number of flips of a fair coin. A password with 8 bits of entropy is as hard to guess as correctly guessing the outcome of 8 consecutive coin flips (1 in 256 chance). A password with 128 bits of entropy is as hard as guessing 128 coin flips (1 in 340,282,366,920,938,463,463,374,607,431,768,211,456 chance).

Our calculator looks at your password through two different lenses to give you a complete picture of its strength.


1. Character-Set Entropy (The Theoretical Maximum)
Formula: Length × log2(Pool Size)

This is the "best-case scenario" entropy. It assumes that every single character in your password was generated by a perfectly random number generator, pulling equally from all available characters.

Pool Size: This is determined by the types of characters you use.
Lowercase letters (a-z) = 26
Uppercase letters (A-Z) = 26
Digits (0-9) = 10
Symbols (!@#$...) = 32
Length: The total number of characters.
Example: If you use only lowercase letters (pool size 26) for an 8-character password, the character-set entropy is 8 × log2(26) = 37.6 bits. If you add symbols and numbers (pool size 94), the entropy jumps to 8 × log2(94) = 52.4 bits.

The Limitation: Character-set entropy has a blind spot. It only cares about what kinds of characters are available, not how they are arranged.

2. Shannon Entropy (The Actual Unpredictability)
Formula: -Σ (p × log2(p)) × Length

Named after Claude Shannon, the father of information theory, this metric doesn't care about your character pool. Instead, it looks at the actual characters you typed and measures how evenly distributed they are.

It looks at the frequency (p) of each unique character.
If every character is totally different, Shannon entropy is high.
If characters repeat, Shannon entropy drops.
Example:

Password: abcABC123 → High Shannon entropy (all unique, evenly distributed).
Password: aaaaaaaa → 0.0 Shannon entropy. Even though the pool size says lowercase letters (26), Shannon entropy reveals that once an attacker guesses the first letter 'a', they have guessed the entire password. There is zero actual unpredictability.
Why Use Both?
If we only used Character-Set Entropy, the password aaaaaaaa would get a score of 37.6 bits (Moderate), which is dangerously misleading.

If we only used Shannon Entropy, the password password would score higher than it deserves, because the English language naturally distributes letters somewhat evenly, but it is still a highly insecure dictionary word.

By combining them:

We use Character-Set Entropy to establish your baseline strength rating (based on length and complexity rules).
We use Shannon Entropy in the background to detect if you are cheating (e.g., repeating characters, using predictable patterns like "qwerty", or just hitting the same key over and over).
